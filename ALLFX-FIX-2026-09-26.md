# SpriteStep ALL^ fix — 2026-09-26 (revision 2)

## Problem

The pre-sprite RG40XXH build could show an ALL^ parameter as `00`, but editing it did not behave correctly. The first fix correctly passed the selected FX code to the renderer, but the input path still had two problems.

## Fixes

1. `native/ui/layout.cpp` passes `seqPatternSelectedFxCode` into the Pattern renderer.
2. `native/ui/input_dispatcher.cpp` opens ALL^ with the Pattern-specific FX layout.
3. The persistent ALL^ picker now treats **A as confirm/close** and **B as cancel/close-with-current-selection**, so the picker cannot intercept an edit gesture after selection.
4. A+UP/DOWN/LEFT/RIGHT while the ALL^ picker is open is routed to the picker rather than the Pattern underneath it.
5. Pressing A on an already-present ALL^ effect no longer resets that effect to `00`. Presence is checked against the selected FX code, rather than the generic `PatternParameter::MORE` enum.
6. Pattern Range Edit now passes the selected ALL^ FX code into its PatternEditorState.
7. Regression tests now exercise the actual `CursorContext` → `increment` / `increment_fast` → `handle_input` path for ALL^ values, including the no-reset behavior.
